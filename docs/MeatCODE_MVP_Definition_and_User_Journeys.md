# MeatCODE MVP Definition & User Journeys

> **This is the project's north star.** Every lane's priorities are judged against the success criteria and journeys below. Source of the alignment broadcast dated 2026-07-22; per-lane gap analysis lives in `docs/MVP_ALIGNMENT.md`.

## MVP Objective
Build a credible, source-backed prototype of MeatCODE that can be
demonstrated internally by the end of August, refined during early
September, and opened to selected external experts for validation by
mid-September.
The primary validation audience is the initial cohort of **P1 expert users**.

## MVP Success Criteria

### 1. Scientific Oracle
A user asks scientific questions about meaty flavor and receives useful,
source-backed answers.
Success criterion: Answers are comparable to or better than those
produced by general-purpose AI systems for representative benchmark
questions.

### 2. GC–MS Interpretation
A user uploads GC–MS data and the system: identifies meaty molecules,
interprets their sensory relevance, connects them to pathways, precursors
and literature, and provides actionable insight.

### 3. Knowledge Discovery
Users can efficiently discover: literature · molecules · reaction pathways ·
protocols · experts · organizations — through an integrated interface.

### 4. Research Planning
Users can transform a scientific question into: relevant literature ·
experimental ideas · protocols · research gaps · potential collaborators.

### 5. Collaboration
Users discover experts and organizations working on similar topics and
identify opportunities for collaboration.

# End-to-End User Journeys

## Journey 1 — Scientific Question
User arrives with a scientific question.
Flow: Question → AI Oracle → Source-backed explanation → References → Follow-up questions.
Success: Answer is genuinely useful and benchmark-competitive.

## Journey 2 — GC-MS Analysis
User uploads analytical GC-MS data.
Flow: Upload → Peak interpretation → Compound identification → Sensory relevance → Reaction pathways → Suggested next experiments.
Success: User obtains insights that normally require extensive manual interpretation.

## Journey 3 — Literature Exploration
User starts with a topic.
Flow: Topic → Relevant papers → Knowledge graph → Important molecules → Methods → Experts.
Success: Rapid understanding of the state of the art.

## Journey 4 — Experimental Design
User wants to design an experiment.
Flow: Research question → Existing knowledge → Protocols → Research gaps → Experimental recommendations.
Success: System accelerates experiment planning.

## Journey 5 — Expert Discovery
User searches for collaborators.
Flow: Topic → Relevant experts → Organizations → Complementary expertise → Contact candidates.
Success: Facilitates ecosystem collaboration.
